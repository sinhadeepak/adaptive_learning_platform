# ADR-0021: Hybrid weekly learning narrative

- **Status**: accepted (frontend + backend shipped — see Phase 5/6 commits)
- **Date**: 2026-05-02
- **Deciders**: CTO, Tech Lead, Product Lead, Editorial Lead, ML Lead
- **Related**: Phase 6 ADR family. Depends on [ADR-0019](0019-ai-gateway-and-consolidation.md) (AI Gateway) and [ADR-0017](0017-multi-parameter-assessment-engine.md) (concept-grain mastery + Bloom + transfer signals). Companion to [ADR-0020](0020-ux-copilot-scope-and-ia.md) (UX Co-Pilot scope).

## Context

The platform records every quiz session, mastery delta, decay event, mock attempt, and session timing. None of it adds up to a story for the student. A repeat student who logs in on Monday morning has no answer to *"what changed last week and what should I do this week?"* — they have to assemble it from `/concept-profile`, `/error-patterns`, `/syllabus`, and the post-quiz AI insight cards. That assembly fails for all but the most motivated students.

The UX Recommendations Review proposes a **weekly learning narrative** as the primary interpretation surface. The reviewer evaluates three options:

| Option | Verdict (per review) | Why |
|---|---|---|
| Pure-freeform AI | Reject as default | Inconsistent across weeks, hard to QA, hard to localise, fails brand voice |
| Pure-template | Reject as final experience | Robotic and repetitive; students recognise the structure within 2 weeks and stop opening it |
| **Hybrid** — fixed sections, AI-written prose, evidence links | **Recommended** | Stable structure for trust + QA; AI prose for non-robotic feel; data links so claims are auditable |

The hybrid posture maps cleanly onto our existing **structured-output discipline** (ADR-0019 §1.3) — the LLM never produces free-form text in production paths; every call passes a JSON schema and is read-through-cached.

## Decision

Adopt the **hybrid weekly narrative** as the platform's interpretation surface. The narrative has a fixed five-section structure; AI generates the prose inside each section subject to a strict structured-output schema; every claim is backed by an "evidence link" the student can tap to drill into the underlying signal.

### Five-section structure (sealed)

| Section | Question answered | Evidence backing |
|---|---|---|
| 1. **What improved** | Where did I make progress? | Per-concept EWA delta over the week (week-end EWA − week-start EWA) ≥ +0.05 |
| 2. **What is slipping** | What needs attention? | Decay arrows where `last_attempted > 7 days` AND mastery > 0.4 (so decay matters) |
| 3. **Hidden pattern** | What behaviour explains results? | Time-of-day accuracy delta, mock-vs-practice delta, careless-mistake rate from S29 error classifier |
| 4. **Forecast** | Where am I headed? | Linear projection from current readiness slope to exam date — surfaces the projected score and one risk |
| 5. **Week ahead** | What should I do? | 3-bullet plan tied to `plan_sessions` rows generated by ADR-0023's plan editor |

These five sections are non-negotiable. The LLM does not pick which sections to render or in which order. A claim in any section that lacks evidence-link data (e.g. forecast for a brand-new user with < 5 sessions) renders the section in a "thin signal" empty-state rather than letting the LLM hallucinate.

### Cadence

| Trigger | Format | Frequency cap |
|---|---|---|
| Sunday 23:00 IST (or Monday morning local) | Full 90-second narrative | At most once per week |
| 5+ meaningful sessions since last full | Mini "what changed" card (only sections that moved) | Once per 5-session window |
| Mock test completed | Mock debrief (timing, stamina, section strategy, readiness implication) | Once per mock |
| Readiness Δ ≥ 5 percentage points | "What changed" card | Once per delta event |

A *meaningful session* is defined per the reviewer's spec: a session that changes mastery/readiness, completes a weak-topic intervention, includes a mock, or produces a repeated error pattern.

### Cost & caching

- Per-narrative LLM cost target: **≤ ₹0.30** (the cost dashboard alerts at 80% / 95% per ADR-0019).
- Cache: one row per `(user_id, week_start)` in `weekly_narratives`. Re-generation on cache miss only; mini-updates write a new row with the same week_start and a delta marker.
- Prompt template: `weekly_narrative@1.0.0` — pinned per ADR-0019 §1.5; bumping the version invalidates cache rows automatically (via the same mechanism as ADR-0019's question-explanation cache).
- LLM provider routing: `touchpoint=evaluation` per ADR-0019 routing config — primary Anthropic, fallback OpenAI; structured-output enforced.

### Evidence links

Every claim in the narrative carries a `data_link` field in the structured output:

```python
{
  "improved": {
    "text": "Your Kinematics accuracy rose from 58% to 71% this week.",
    "data_link": {
      "kind": "concept_mastery_delta",
      "concept_id": "<uuid>",
      "before": 0.58, "after": 0.71,
      "n_sessions": 4
    }
  },
  ...
}
```

The frontend renders the `text` and exposes `data_link` behind a *"Why am I seeing this?"* tap target that opens the relevant evidence drawer. **Claims without backing evidence are not rendered.**

## Alternatives considered (rejected)

- **Pure-freeform AI narrative.** Rejected — inconsistent QA, fails Hindi narrative parity, no auditable evidence backing.
- **Per-day daily narrative.** Rejected — cost (~7× per user per week) without comparable engagement uplift; daily attention belongs to Today's Mission (ADR-0024), not narrative.
- **Render structured payload as bullets, no AI prose.** Rejected — explicitly the "robotic" failure mode the reviewer flags; students stop opening it after week 2.
- **Generate narrative on every quiz submit.** Rejected — bursts LLM cost; weekly + event-triggered is the right granularity. The reviewer's 5-meaningful-session trigger already captures bursts.
- **Skip the cache layer.** Rejected — same reason ADR-0019's question-explanation cache exists; without caching, even one student-pair viewing the narrative twice doubles spend.

## Consequences

### Positive

- **Predictable weekly mental model.** Students know that on Monday morning they read the narrative; the format is the same every week; the story changes.
- **Trustable claims.** Every assertion is backed by data the student can drill into. No hallucinated mastery deltas.
- **Editorial governance.** Editorial / SME team can review the prompt template's output on a rolling sample — same Cohen's-kappa pattern as the S43 calibration pipeline.
- **Cost-bounded.** Caching + cadence caps + structured output keep weekly-narrative cost predictable. The cost dashboard will show this as a discrete touchpoint.
- **Localisable.** Translation pipeline (S43) treats the narrative payload like any other artifact — `translatable_fields()` walks the `text` strings; numeric data and concept IDs are left intact.

### Negative

- **Bootstrap friction.** A new student with < 5 sessions can't generate a meaningful narrative. Mitigated by: render a "thin signal" empty-state with the screening-test diagnostic + one explicit "complete 3 more sessions to unlock your weekly story" CTA.
- **Same prompt → same prose risk.** If two weeks of signals are highly similar, the narrative may read similar. Mitigated by: include the previous week's narrative in the prompt context for variation, plus a 200-character minimum delta requirement before a section can re-use a pattern.
- **Mock debrief cadence may collide with weekly cadence.** A student who takes a mock on Sunday gets two narratives back-to-back. Mitigated by: 24-hour suppression — if a full weekly narrative was generated in the last 24 hours, the mock debrief renders as an addendum block to the existing weekly card.
